# habitat-radiomics-pca-lnm

Analysis code and derived data for

> **Preoperative Lymph Node Staging in Prostate Cancer: Endpoint-Driven
> Purification Outperforms Richer Intratumoral Decomposition**

The repository reproduces **every number in the manuscript and the supplementary
material** from the derived data that ship with it.  No imaging data are needed.

```bash
python -X utf8 verify/check_paper_numbers.py
```

`DISCREPANCY` = a published value that does not follow from the released data;
`SKIP` = not derivable from the release (no imaging data / no identifier linkage).

`src/hrpca/paper.py` — nothing is hard-coded — and the verifier carries a source
guard that fails if the wrong manuscript file is read.  If a source it needs is
unavailable, the verifier exits **3** and says so, instead of reporting a
numerical failure.

## 2 · What the study did

A fully automated, contrast-free biparametric MRI (T2WI + DWI + ADC) habitat
radiomics pipeline for preoperative pelvic lymph node metastasis (LNM) in
prostate cancer: 1,016 patients from three centres, developed in 398 and
validated in two external cohorts (339 + 189) and a prospective cohort (90).

| Step | Method |
|---|---|
| Segmentation | 3D nnU-Net on T2WI (Dice 0.95 vs manual delineation, n = 30) |
| Level-1 clustering | voxel-wise K-means on ADC/DWI/normalised T2WI inside the gland; K = 2 by the Calinski–Harabasz index; the lowest-mean-ADC cluster is the target region |
| Level-2 clustering | voxel-wise K-means on local texture inside that region; **K = 5** selected by repeated 10×10-fold cross-validation on the clinical endpoint |
| Features | PyRadiomics 3.0.1 (IBSI), region-remapping aggregation → 1,197 candidates |
| Selection | ICC ≥ 0.80 → near-zero variance → collinearity (\|r\| ≤ 0.9) → LASSO (λ = 0.0233) → **27 retained** |
| Models | clinical (ISUP + PI-RADS, LR), habitat-specific (H1–H5), all-habitat (27 features, LR), **combined** (clinical probability + H2 + H4, LR) |
| Comparators | information-matched multisequence whole-tumour radiomics; 3D ResNet-18 |

## 4 · Data availability and ethics

> **The individual-level analysis dataset is not publicly available; it may be
> obtained from the corresponding author under a data-use agreement and with
> institutional approval.  A synthetic dataset with identical structure is
> provided so the pipeline can be run end-to-end.**

This repository contains **no patient-level record**.  The trial registration
(ChiCTR2500111002) states *IPD sharing: No*, so the per-patient tables — clinical
variables, habitat radiomics features, per-signature scores, the identifier key
and the per-patient SHAP values — live in a **controlled institutional store**
outside version control.  The same applies to the run outputs under `results/`,
which are derived from those tables.

**Raw imaging (DICOM/NIfTI), the segmentation masks and the trained network
weights are likewise not distributable** (patient privacy and the terms of the
institutional review board approvals).

|---|---|---|

they never report PASS on an empty dataset:

| `verify/scan_identifiers.py --gate` | still runs and still passes — it scans the repository, which now holds no patient-level data |

### ⚠️ F8 — the habitat feature tables are not the modelling matrix

*(Recorded while the individual-level tables were still in the repository; it
documents a property of the archive, not of the synthetic set.)*

Refitting a logistic model on the 27 retained features taken from the habitat
feature tables gives a **training AUC of 0.745–0.756**, and the archived
coefficient file applied to the same columns gives **0.700**; neither reproduces
the reported **0.864**.  The frozen per-patient scores do give 0.864.  The
delivered feature tables were therefore re-extracted *after* the production run
and are **not** the matrix on which the reported model was fitted.  All 87 cells
of the retained-feature table (names, habitats, RF importance, mean |SHAP|) are
reproduced from `data/shap/SHAP_k5_feature_stats.csv`, so the retained set itself
is consistent.  `src/04_feature_selection.py` documents this and will not
silently return a different 27-feature set.

## 5 · Conventions the numbers depend on

### 5.1 Statistical conventions

| # | Convention | What changes otherwise |
|---|---|---|
| 1 | Training-cohort AUCs use the **16-significant-digit** export (`data/scores_highprec.csv`) | the released training scores are rounded to two decimals → clinical AUC 0.704 instead of 0.706, all-habitat 0.863 instead of 0.864 |
| 2 | The **combined** model's training AUC uses the deployed scores (`data/scores/train.csv`) | the `Combined` column of the historical 16-digit export is a **superseded model** → 0.795 instead of 0.798 |
| 3 | mean \|SHAP\| uses the **full 398-patient training cohort** as the reference | the 391-row subset used to draw the panel gives 0.561 for H4 instead of 0.565 |
| 4 | Hosmer–Lemeshow: **Table S9 = 10 equal-frequency bins, df = bins − 2 = 8**; the **Clinical row must use rank-split bins** | with quantile-edge (`qcut`) bins the clinical row becomes 0.0343 / 0.0007 / 0.0350 / 0.1162 instead of 0.012 / 0.0004 / 0.091 / 0.380 |
| 5 | The combined model is **linear in probabilities, not log-odds** | required for the closed-form SHAP attribution `βᵢ(xᵢ − E[xᵢ])` and for the published coefficients |
| 6 | Cox recalibration is fitted **within each cohort** | the pooled-external intercept/slope (−0.513 / 1.239) require pooling the three external cohorts first |
| 7 | IDI is `Δ(mean p \| event − mean p \| non-event)` on the probability scale | the log-odds variant gives 0.72 instead of 0.124 for the training cohort |
| 8 | `base.csv` = mean `f(x)` over all 1,009 rows of `meta_all.csv` (−1.1039913); the 391-row training subset gives −1.1047250; the 398-patient training cohort from the deployed scores gives −1.1039943 | mixing the three gives a spurious 7 × 10⁻⁴ difference |

### 5.2 Rounding notes (not errors)

| Item | Explanation |
|---|---|
| Table 2, ResNet-18 T2WI test cohort 1 | the manuscript prints **0.557**; `dl_comparator_results.csv` stores 0.556500, which rounds to 0.557.  The comparator CSV supplied with the submission stores 0.556 — the same value at different precision |
| Table S10, training-cohort ΔAUC | prints **+0.092**, which is the difference of the table's own two rounded AUCs (0.798 − 0.706).  The unrounded difference is **+0.0942**; the table is internally consistent |

## 7 · The cross-table identifier key

`Clinic.csv` (numeric ID), `label.csv` (`.nii.gz` file names) and the score files
(within-cohort row index) share **no** key.  The link is
`data/cases_with_ids.csv`:

```
derived_data/<cohort>_scores_label.csv
      │ (patient_index)     ← the eight score columns are byte-identical
      ▼
cases_with_ids.csv  ──(real_id)──►  Clinic.csv
                    ──(real_id)──►  label.csv
                    ──(real_id)──►  heatmap_data_all.csv / _fullprec_scores.csv
```

| Check | Result |
|---|---|
| `(cohort, patient_index)` unique / `real_id` unique | 0 duplicates ✅ |
| `real_id` present in `label.csv` / `Clinic.csv` / heatmap | 1016/1016 · 1005/1016 · 1016/1016 |
| Fingerprint (unrounded clinical probability recovered through `real_id`) | test 1 **339/339** (r = 1.0000); test 2 **189/189** (r = 1.0000); **training 0/398** ✗ |
| Positional join, as a control | test 1 **36/339**; test 2 **14/189** ✗ |
